# Decisions

Choices made without asking, newest scope first. Revisit any of these freely.

## Scope
- **Front end only.** React + Vite + TypeScript (per your direction). No backend, no Next.js. Supabase comes later.
- **Backend-shaped front end.** The UI only talks to the interfaces in `src/data/services.ts` (`AuthService`, `PlacesService`, `JournalRepo`, `PhotoStore`). `src/data/local/*` implements them with localStorage + IndexedDB. The Supabase step adds `src/data/supabase/*` and changes the 5 lines in `src/data/index.ts`.
- **Types mirror the brief's Postgres model**, camelCased. Dishes and tag ids live on the visit object locally; in SQL they are `visit_dishes` / `visit_tags` (see `docs/schema.sql`).

## Stack
- **Vite 8 + React 19 + TS (strict), React Router 7 (data router), TanStack Query**: Query gives the same cache/mutation shape we want over Supabase.
- **Tailwind v4 with hand-written shadcn-style primitives** (`src/components/ui`, built with `cva` + `tailwind-merge`). I did not run the shadcn CLI: it overwrites the theme tokens and I wanted tight control of 44px tap targets. Individual shadcn components can still be dropped in later.
- **PWA via `vite-plugin-pwa`** (manifest, Workbox service worker, offline shell). Placeholder icons are generated by `scripts/make-icons.ts`.
- **Map: MapLibre GL** instead of Mapbox GL / Google Maps. It is the open-source fork of Mapbox GL, same API, and needs no key. Tiles are OSM demo tiles; swap for a hosted tile provider before launch (OSM's usage policy doesn't allow heavy production use). Loaded lazily, only on the Map tab.

## Product decisions
- **Log flow**: the visit row is created the moment a place is tapped, before any details. The details sheet autosaves (taps immediately, text after 500ms and on blur/leave). Tapping "Search a place" result is tap 1 of 3 after the log screen opens; the search box is visible on arrival so it needs no tap.
- **Photos**: EXIF is read from the original file, then the image is downscaled to 1600px JPEG (which strips EXIF) and stored in IndexedDB. Photos picked but never attached to a visit stay "unattached" and drive the nudge banner (last 7 days).
- **Photo to place**: nearest fixture places within 600m, top 3. No GPS or no nearby places falls back to search with a friendly note, never an error.
- **Feeling default**: choosing Loved/Liked turns "I'd recommend it" on, Meh turns it off. The user can override.
- **Recs** only include recommendable visits. One entry per place, best-feeling visit represents it. Order: feeling (loved > liked > meh), then most recent. Occasion matches if any visit of the place has the tag. Price uses the price you paid, falling back to the place's price level.
- **Empty rec state** names the single constraint whose removal yields the most matches and offers a one-tap "Drop" button.
- **My places filters**: AND across groups, OR within occasion tags and within vibe tags. Text search covers name, cuisine, neighborhood, dishes and notes (accent-insensitive).
- **Tags**: occasion = date night, groups, solo, family, impress visitors, brunch, late night, quick bite; vibe = cozy, lively, outdoor. ("quick bite" reads as an occasion to me.)
- **Auth**: mock magic link. Enter email, then a dev-only "Open magic link" button calls `/auth/callback`. `alanna@example.com` is pre-seeded with the demo journal. Any other email starts empty. "Try the demo journal" signs in as Alanna.
- **No rankings, scores or leaderboards** anywhere; "Loved it / Liked it / Meh" is a private feeling, used only to order your own recs.

## Sharing (the main compromise of going front-end-only)
- `/r/:slug` is a client route. The card content (`RecPayload`) travels in the URL hash (`#d=<base64url JSON>`), so a link opens logged-out on any device with no server. Photos are too big for a URL, so cross-device viewers see a gradient placeholder; the sharer's own browser also has a small thumbnail in the local share record.
- **Real Open Graph previews are stubbed.** A static SPA can't emit per-URL `<meta>` tags or an `og:image` for crawlers (iMessage/WhatsApp don't run JS). The page sets `og:*` tags client-side (tested) and `/r/:slug/card` renders the 1200x630 layout as HTML, ready to be rendered server-side (Edge Function / `@vercel/og`) in the backend step.
- "Reserve" links to the place's website, or a Google search for reservations when there is none.
- View counts only update locally for now.

## Fixture data
- `src/data/fixtures/places.ts`: 41 Atlanta restaurants used as the Places stand-in. Names are real-world examples but **cuisine, price and coordinates are illustrative** (neighborhood center plus a small grid offset, ~130m apart so photo matching is unambiguous). Replace with Google Places (New) in the backend step; calls must go through a server function so the key never ships in the browser, and results should be cached in `places`.
- `src/data/fixtures/seed.ts`: 16 demo visits relative to today, 4 want-to-try items, 1 share.
- `e2e/fixtures/*.jpg` are generated with real EXIF by `scripts/make-fixture-photos.ts`.

## Deferred to the backend step
Supabase Auth (real magic links), Postgres + RLS **and the RLS test** (`docs/schema.sql` has a starting schema and policies), Storage for photos, server-side OG images, Google Places proxy + caching, shared-link view counts, Vercel env config.
